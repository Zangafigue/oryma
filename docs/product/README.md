# Documentation produit

Ce dossier définit le besoin et les comportements attendus avant les choix d’implémentation.

## Documents

1. [Cahier des charges](cahier-des-charges.md) — contexte, objectifs, périmètre, contraintes, livrables, critères d’acceptation.
2. [Termes de référence](termes-de-reference.md) — objet de la mission, résultats attendus, méthodologie, organisation, calendrier et évaluation.
3. [Product Requirements Document](product-requirements.md) — problème, personas, périmètre, priorités et critères de réussite.
4. [Software Requirements Specification](software-requirements.md) — exigences testables, règles métier, contraintes non fonctionnelles et cas d’erreur.

Une modification du périmètre commence dans le PRD. Une modification du comportement attendu commence dans le SRS et doit ensuite être répercutée dans l’architecture, les contrats et les tests concernés.
